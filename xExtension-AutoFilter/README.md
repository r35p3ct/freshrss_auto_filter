# FreshRSS Auto Filter Extension

Расширение для автоматического определения и фильтрации рекламных записей в FreshRSS с использованием AI (OpenRouter API).

## Возможности

- **Автоматическое определение рекламы** с помощью AI (OpenRouter API)
- **Гибкая система меток** (бинарное решение):
  - `Реклама` — модель ответила «реклама» с уверенностью не ниже порога (помечается прочитанной)
  - `Непроверено` — запись ожидает фоновой проверки
  - Историческая метка `Подозрение` больше не присваивается
- **Фоновый режим проверки** — записи добавляются мгновенно, AI-проверка идёт отдельным скриптом
- **Предварительный фильтр по ключевым словам** — LLM-проверка только записей с заданными словами, остальные пропускаются без запроса к API
- **Настраиваемые пороги уверенности** для точной настройки фильтрации
- **Валидация конфигурации** — автоматическая проверка корректности настроек
- **Безопасное логирование** — метаданные вместо полного содержимого записей

## Установка

1. Скопируйте папку `xExtension-AutoFilter` в директорию расширений FreshRSS:
   ```
   ./extensions/xExtension-AutoFilter/
   ```

2. Включите расширение в настройках FreshRSS:
   - Перейдите в `Настройки` → `Расширения`
   - Найдите `Auto Filter` и нажмите `Включить`

3. Создайте необходимые метки в FreshRSS:
   - `Реклама`
   - `Подозрение`
   - `Непроверено`
   - `Проверено`

## Настройка

### API ключ

Получите API ключ на [openrouter.ai/keys](https://openrouter.ai/keys)

### Модель

Чат-модели (генерируют JSON-ответ):
- `openai/gpt-3.5-turbo` — быстро и недорого
- `openai/gpt-4o-mini` — более точное определение
- `anthropic/claude-3-haiku` — хорошая альтернатива

Модели решений System One (рекомендуется):
- `typesafe/jev-1.13` (стабильная) или `~typesafe/jev-latest` (катится вперёд)
- Работают через отдельный OpenRouter API структурированных решений: вместо генерации JSON возвращают калиброванную вероятность «рекламы» (noul)
- Порядка $0.042 за миллион входных токенов (вывод бесплатный), латентность ~0.2–0.7 с
- Промт из настроек для них не используется — критерии заданы в коде

### Порог уверенности

- **Порог для «Рекламы»** (по умолчанию 0.7) — метка ставится только если модель ответила `is_advertisement = true` и её уверенность не ниже порога. Иначе запись не помечается. Решение бинарное: «Реклама» или ничего, режим «Подозрение» убран.

### Предварительный фильтр по ключевым словам

Чтобы не тратить запросы к AI API на все записи подряд, задайте ключевые слова (настройка **«Ключевые слова (предварительный фильтр)»**):

- Если список **не пуст** — через AI проверяются только записи, в заголовке или тексте которых встречается хотя бы одно из слов; остальные пропускаются без LLM-запроса.
- Если список **пуст** — проверяются все записи выбранных каналов (как раньше).
- Одно слово или фраза на строку (можно и через запятую). Поиск — по вхождению без учёта регистра, поэтому удобно указывать основу слова: `подписыв` покроет «подписывайтесь», «подписывайся» и «подписывайтесь на канал».

Фильтр работает до применения метки `Непроверено`, поэтому в фоновой проверке участвуют только записи, прошедшие отбор.

### Фоновый режим (рекомендуется для API-клиентов)

Если вы используете CapyReader, Fluent Reader или другие клиенты через Fever/GReader API и сталкиваетесь с задержками при обновлении лент:

1. Включите **Фоновый режим проверки** в настройках расширения
2. Настройте размер пачки (сколько записей проверять за раз, по умолчанию 10)
3. Настройте задержку между запросами (по умолчанию 250 мс — для моделей System One этого достаточно)
4. Добавьте в cron задачу для запуска фонового скрипта:

```bash
# Каждые 5 минут
*/5 * * * * php /path/to/freshrss/extensions/xExtension-AutoFilter/scripts/process_pending.php
```

Для Docker:
```bash
*/5 * * * * docker exec freshrss php /var/www/FreshRSS/extensions/xExtension-AutoFilter/scripts/process_pending.php
```

**Как это работает:**
- При обновлении лент новые записи мгновенно добавляются с меткой `Непроверено`
- Фоновый скрипт постепенно проверяет их через AI и заменяет метку на результат (`Реклама`, `Подозрение` или удаляет)
- При чтении через API-клиенты новости отдаются мгновенно, без задержек на AI-проверку

### Промт по умолчанию

Расширение использует оптимизированный промт с чётким форматом вывода JSON. Вы можете задать собственный промт, используя плейсхолдеры:
- `{title}` — заголовок записи
- `{author}` — автор
- `{url}` — ссылка
- `{content}` — содержимое

### Логирование

При включённом логировании записываются:
- Метаданные промпта (длина, количество авторов)
- Краткий preview ответа API (первые 100 символов)
- Результат анализа (метка, уверенность, причина)

> **Примечание:** Полное содержимое записей не логируется для защиты конфиденциальности.

## Использование

### Автоматическая проверка (синхронный режим)

Расширение автоматически проверяет новые записи при их получении через хук `entry_before_add`.

> **Внимание:** В синхронном режиме каждая новая запись блокирует добавление до завершения AI-запроса. Это может вызывать задержки при чтении через API-клиенты.

### Ручная проверка

1. Найдите кнопку 🛡️ в заголовке записи
2. Нажмите для проверки записи на рекламу
3. Запись будет помечена соответствующей меткой

### Фильтрация по меткам

Используйте встроенные средства FreshRSS для фильтрации:

1. Создайте ярлык с фильтром по метке:
   - `label:Реклама` — показать только рекламу
   - `-label:Реклама` — скрыть рекламу
   - `label:Подозрение` — показать возможные рекламы

2. Используйте ярлыки для быстрого доступа к отфильтрованным записям

## API

### Проверка одной записи

```
GET /api/p.php?c=autoFilter_openrouter&a=checkEntry&entry_id={ID}
```

Ответ:
```json
{
    "success": true,
    "entry_id": 123,
    "analysis": {
        "is_advertisement": true,
        "confidence": 0.95,
        "reason": "Коммерческое продвижение товара",
        "label": "Реклама"
    }
}
```

### Массовая проверка

```
POST /api/p.php?c=autoFilter_openrouter&a=checkBatch
{
    "entry_ids": [123, 456, 789]
}
```

## Требования

- FreshRSS 1.20 или выше
- PHP 7.4 или выше
- API ключ OpenRouter

## История изменений

### Версия 0.6.0

- **Бинарная логика**: режим «Подозрение» убран — только «Реклама» или без метки, один порог уверенности
- **Модели решений System One (TypeSafe Jev)**: вызов через отдельный API, калиброванная вероятность вместо генерируемого JSON
- **Универсальный промт по умолчанию** без лестницы уровней уверенности
- Задержка между запросами по умолчанию 250 мс

### Версия 0.5.0

- **Предварительный фильтр по ключевым словам** (`keywords_filter`): при заданных словах LLM-проверяются только записи с их вхождением, остальные пропускаются без запроса к API
- Пустой список слов — прежнее поведение (проверяются все записи выбранных каналов)

### Версия 0.4.0

- **Добавлен фоновый режим** проверки записей
- **Новые метки**: `Непроверено` и `Проверено`
- **CLI-скрипт** `scripts/process_pending.php` для фоновой обработки
- **Настройки batch_size и request_delay_ms** для контроля нагрузки на AI API
- **Устранены задержки** при чтении через API-клиенты (CapyReader и др.)

### Версия 0.3.1

- Переход на хук `entry_before_add`
- Использование `TagDao` для работы с метками
- Исправлено применение меток до вставки в БД

### Версия 0.3.0

- Добавлено кэширование результатов анализа
- Добавлена валидация входных данных
- Добавлены константы для меток
- Улучшено логирование

### Версия 0.1.1

- Начальная версия с базовой функциональностью
